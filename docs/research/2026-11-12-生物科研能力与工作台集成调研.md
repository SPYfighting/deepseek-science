# 生物科研能力与工作台集成调研

日期：2026-11-12  
用途：为 DSH science“科研工作台”重构提供可追溯的一手证据；重点支持“图表与成果”“专家配置”“团队进展”和主面板接入。  
范围：仅核对项目官网、官方 GitHub 仓库、仓库源码及当前项目已安装的 DSH 包源码。下文把实际观察与集成建议分开；“可安装技能”只指已核实存在 `SKILL.md` 的仓库，不把普通科学工具仓库误标为技能。

## 结论先行

1. **ScientificFigureLibrary（SFL）可作为本地科研图模板、版本、来源和许可管理层**，并且自身带 `SKILL.md`、MCP server/MCP App 和 DSH 插件安装入口；它不执行绘图代码。SFL 主程序是 MIT，但图库资产按来源分别许可，不能一概当作 MIT。
2. **BioRender 是专有的外部授权服务，不是可内置的开放图标库，也未核实到官方公开 `SKILL.md`。** 合理集成是账号授权连接器或“在 BioRender 中打开”，不能把其图标、模板抽取后打包进 DSH 或开放图库。
3. **K-Dense 的 `scientific-agent-skills` 与 `drug-discovery-agent-skills` 是已核实可按 `SKILL.md` 安装的技能仓库。** 可直接覆盖 OpenMM 分子动力学、Boltz、AutoDock Vina、RDKit、ESM 和科研绘图；GROMACS、AlphaFold/ColabFold/Chai、gnina、ProtT5 在本次核对的技能仓库中没有对应的专用 `SKILL.md`，应标为“工具/模型候选，未安装技能”，不能让“安装”按钮假装已经集成。
4. **DSH 0.2.2-rc.1 支持完整中央主面板。** 主页面注册到根作用域 keyed slot `main`，左侧入口注册到 `sidebar.panellist`，两者使用相同 id。`main` 中除 `conversation` 外的全局页面没有 Session binding；要把专家卡片变成提示词，必须先确定当前 `mainView` 保留的会话，再通过 `ctx.sessions.binding(id)?.session.prompt(...)` 发送，或显式 `retain/using` 并管理生命周期。
5. **当前 DeepSeek 官方 `agent-team` 包没有完整 `ActivityPanel`/依赖图。** 它提供的是基于 `TeamAction` 的成员和任务浮层。仓库中的完整 `ActivityPanel`、`DependencyMap`、`compactDagLayout` 来自第三方 `NanmiCoder/dsh-agent-teams`（MIT）；可借鉴或按许可复用，但必须保留来源，不应标成官方稳定接口。

## 1. 科研绘图能力

### 1.1 ScientificFigureLibrary

**实际观察**

- SFL 是 local-first 的 MCP server 与 MCP App，管理“图像 + 绘图代码 + 元数据 + 审查/发布状态”，可为 Codex、Claude、Cursor、Pi、dsh、Wisp 等宿主提供同一图库；SFL 自身不执行绘图代码。来源：[官方 README](https://github.com/xuzhougeng/ScientificFigureLibrary)、[协议说明](https://github.com/xuzhougeng/ScientificFigureLibrary/blob/main/docs/PROTOCOL.md)。
- 仓库确有可安装技能入口 [`skills/figure-library/SKILL.md`](https://github.com/xuzhougeng/ScientificFigureLibrary/blob/main/skills/figure-library/SKILL.md)，并记录 DSH 安装方式 `dsh plugin --profile web add scientific-figure-library`。因此它属于“**技能 + MCP/插件能力**”，而不是仅有绘图库源码的普通仓库。
- SFL 软件代码采用 MIT；导入资产不被 SFL 重新许可，FigureYa、community 模板代码、预览和文档等还有不同的 CC/MIT 条款。来源：[LICENSE](https://github.com/xuzhougeng/ScientificFigureLibrary/blob/main/LICENSE)、[THIRD_PARTY_NOTICES](https://github.com/xuzhougeng/ScientificFigureLibrary/blob/main/THIRD_PARTY_NOTICES.md)。
- MCP App 可以申请 fullscreen 或 picture-in-picture；它不是 DSH `sidebar.panellist`/`main` 原生页面的替代。宿主已有插件时不要同时重复注册 raw MCP，以免出现重复工具。

**集成建议（推断）**

- 专家卡片标记为“可安装插件/技能”，安装后作为“模板检索—审查—发布—物化”入口；绘图执行仍交给 Python/R/宿主代理。
- 每个图模板显示 `source`、`license`、`attribution`、`review state`；不因 SFL 主代码是 MIT 而隐藏资产的非商业或署名限制。
- DSH 自己的“图表与成果”页只索引最终文件和来源清单，不复制 SFL 的完整管理界面。

### 1.2 BioRender

**实际观察**

- BioRender 官方支持在 ChatGPT、Claude、Copilot 中通过连接器搜索公共模板和用户文件、生成草稿，再回到 BioRender 编辑器完成编辑；每名成员需登录并授权自己的 BioRender 账号。来源：[BioRender 官方帮助：Use BioRender with AI assistants](https://help.biorender.com/hc/en-gb/articles/39961737589277-Use-BioRender-with-AI-assistants)。
- BioRender Content（图标、模板、插画等）为专有内容。免费/试用方案通常不提供论文发表权；付费 Academic/Industry 方案及导出的 Publication License 决定发表使用范围。来源：[Basic License](https://www.biorender.com/basic-license)、[Licensing and usage](https://help.biorender.com/hc/en-gb/articles/17605388551197-Licensing-and-usage-of-figures-made-in-BioRender)、[Publication license](https://help.biorender.com/hc/en-gb/articles/17605463719709-Publication-license-Terms-of-use)。
- 官方条款禁止把底层图标单独下载、提取或做成面向第三方的可分发模板。官方帮助中心和域名验证的 [BioRender-Team GitHub 组织](https://github.com/BioRender-Team) 中未核实到公开 `SKILL.md`。这是本次检索结果，不是对私有实现的否定。

**集成建议（推断）**

- 在 DSH 中标记为“外部连接器/服务”，不是“开源技能”或“内置资产库”。若运行环境存在已授权连接器，按钮可转到该能力；否则只提供官网入口和许可提示。
- 不把 BioRender 图标、模板导入 SFL 或 DSH 公共模板库。只保存用户导出的 completed graphic、引用文字、导出日期和 Publication License。
- 在发送提示词或文件给连接器前显示数据外传说明；BioRender 官方说明查询、选择对象、提示词和生成草稿会与相应 AI 助手共享。

### 1.3 scientific-agent-skills

**实际观察**

- [`K-Dense-AI/scientific-agent-skills`](https://github.com/K-Dense-AI/scientific-agent-skills) 是 Agent Skills/Agent Plugins 仓库，每个技能以 `SKILL.md` 为入口，支持 `npx skills add K-Dense-AI/scientific-agent-skills`、GitHub CLI 安装、按单个技能安装或手工复制；仓库为 MIT。安装前仍须审阅技能，因为技能可能运行代码、联网、安装包和修改文件。来源：[README](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/README.md)、[LICENSE.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/LICENSE.md)。
- 与绘图直接相关的可安装技能：
  - [`scientific-visualization/SKILL.md`](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-visualization/SKILL.md)：本地 Matplotlib/Seaborn/Plotly 数据图、审查、期刊导出和 provenance；自动检查不等于科学正确性。
  - [`scientific-schematics/SKILL.md`](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-schematics/SKILL.md)：经 OpenRouter/图像模型生成栅格示意图并复核；需要网络/API key，提示词和图像会外传，且不是可编辑矢量成品。

**集成建议（推断）**

- `scientific-visualization` 可作为默认本地数据图技能；`scientific-schematics` 应显示“联网、付费 API、栅格输出、不可发送未发表/患者数据”的风险徽标。
- 与 SFL 组合时，前者负责生成和审查，后者负责模板复用、版本及来源链；不要把两者合并成一个含糊的“AI 绘图”开关。

## 2. “专家配置”候选目录

### 2.1 必须采用的类型标识

| 标识 | 判定标准 | UI 行为 |
|---|---|---|
| 可安装技能 | 已核实存在 `SKILL.md`，并有宿主安装方式 | 可提供“查看说明/安装”动作；安装前展示来源、固定版本、权限和外传边界 |

### 2.4 专家卡片最小字段

每张卡片至少显示：

- `kind`：技能 / 工具 / 外部服务；
- `source`：官方仓库或官方服务链接；
- `skill_entry`：存在时给出精确 `SKILL.md`，不存在则明确写“无已核实入口”；
- `license`：代码、模型权重、资产分别记录；
- `runtime`：Python/Node、操作系统、CUDA/GPU、数据库和磁盘要求；
- `network`：是否调用 MSA server、API 或外部模型；
- `data_boundary`：序列、结构、患者信息或未发表数据是否离开本机；
- `install_state`：未安装 / 已安装 / 需外部配置 / 不可自动安装；
- `version_pin`：安装的 tag/commit 与检查日期；
- `validation`：最小真实输入、预期产物和不应过度解释的模型分数。

## 3. DSH 工作台一手接口证据

**实现含义（推断）**：全局科研工作台的“开始绘图/配置专家/打开对话”等动作不能假定组件 props 已带当前 session。先从 `useSessions`/`ctx.sessions.list` 找出 `retainedBy.mainView > 0` 的会话；若已保留，可取 `ctx.sessions.binding(id)?.session`，再按 DSH 的提交流程调用 `beginSubmission` 与 `prompt`。没有当前会话时，按钮应引导创建/打开会话，而不是静默失败。若工作流自行 `retain`，必须在操作结束后 release，避免泄漏引用。

## 4. 推荐接入顺序

1. 先按 DSH 契约建立 `main` + `sidebar.panellist` 同 id 的空主面板，并验证从对话切换到工作台、再返回对话不会改变当前 Session。
2. 为主面板建立唯一的“当前会话解析 + prompt 提交”适配层，统一处理无会话、`queue/steer`、submission echo、业务错误和引用释放。
3. 专家目录先接入已核实的 `SKILL.md`：OpenMM MD、Boltz、Vina、RDKit、ESM、scientific-visualization、SFL；安装动作必须固定版本并展示权限。
4. GROMACS、AlphaFold、ColabFold、Chai、gnina、ProtT5 先作为“工具/模型”卡片，仅生成配置或安装计划；为每项另写、审查并最小验证内部技能后，才升级为“可安装技能”。
5. BioRender 保持外部连接器；任何环境未提供已授权连接器时不展示虚假的“一键安装”。
6. 团队页先复用官方投影读取方式；若引入社区 DAG 算法，单列第三方声明并用本项目测试数据验证布局、循环/缺失依赖和大任务量退化行为。

## 5. 未确定项与边界

- 本文没有实际安装或运行任何科学软件、模型权重或技能；运行时兼容性必须在实现阶段用最小代表性真实输入验证。
- 技能仓库会持续变化。“未找到专用 `SKILL.md`”只表示截至 2026-11-12 对上述官方/指定仓库的核查结果；实现时应固定 tag/commit，而不是依赖漂移的 `main`。
