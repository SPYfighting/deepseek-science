# 科研工作台重构设计

日期：2026-11-12  
状态：用户已确认路线；待接手 Agent 实施与本会话验收  
目标版本：v0.15.0（暂定）

## 1. 背景与已观察问题

本轮目标不是继续给现有页面补样式，而是把插件从“对话中的技能集合”改造成“以论文工作流为中心的可视化科研工作台”。对话仍然存在，但承担补充要求、复杂修改和解释，而不是唯一入口。

实际检查得到以下结论：

1. `/sci-hypothesis` 当前存在确定性错误。命令处理器把普通字符串传给 `Agent.followup()`；DSH 0.2.2 的接口要求完整 `UserMessage`。最小复现中，处理器返回 success，但入队值类型为 string，因此后续智能体轮次可能以“处理失败”结束。
2. 自定义 `/sci-hypothesis` 命令还遮蔽了 DSH 的同名技能手势。正常的 `/skill-name` 本应由宿主确定性注入技能正文，现在却退化成提示模型“请加载技能”。
3. 当前工作台仅注册在右侧栏。首次打开右栏时，用户先看到“开始/工作区文件/终端”，再从说明文字中寻找“科研工作台”，缺少独立主入口。
4. 当前“论文驾驶舱”主要展示状态，没有能直接启动探索、生成结构、细化任务、绘图、写作或制作汇报的操作。所谓命令 chip 只是复制文本。
5. “团队执行”混入角色技能安装，执行监控与专家配置职责不清。
6. “论文证据主干”“论文驾驶舱”“Claim—证据关系图”“审计冻结”等术语偏内部实现，不适合作为首次使用界面。
7. 全屏视觉仍接近调试面板：字号偏小、留白和层级不足、交互反馈弱、卡片密度失衡，缺少成熟 AI Web 产品应有的起始引导、主要动作和错误恢复。
8. 专家增强目录包含燃烧、CFD 和通用 LLM 微调等偏离生物科研主线的项目，缺少蛋白质结构预测、分子动力学、分子对接、蛋白质语言模型和生物科研绘图能力。

## 2. 产品意图

目标用户是不需要了解技能名、工具名和内部数据结构的生物科研人员。用户应能从一个明确入口开始工作，并在同一界面中看到：

- 论文当前处于哪个阶段；
- 下一步最值得做什么；
- 每个研究结果还缺什么；
- 哪些任务正在由谁执行；
- 已生成哪些图表、文稿和汇报材料；
- 哪些专家能力可按需增强。

工作台发起的操作必须与当前 DSH 会话互通。按钮不直接绕过智能体修改科学结论，而是把结构化请求提交到当前会话；需要确认的科学主张继续使用 DSH 原生审批卡。

## 3. 目标、非目标与反目标

### 3.1 目标

1. 新用户在进入工作台后 10 秒内能找到“开始探索”或“导入已有结果”。
2. 用户不需要记忆 `/sci-*`、`sci_*`、Claim、Evidence Spine 等内部名称。
3. 论文阶段和 Result 状态既能查看，也能点击推进、修改或退回。
4. 论文结构、任务执行、图表成果和专家配置各自成为独立页面。
5. 每个动作都具有明确输入、结果、失败原因和恢复入口。
6. 保留“未确认不能正式派单”的约束，不用 UI 便利性削弱科学确认闸门。
7. 默认专家增强目录围绕生物信息学、结构生物学、分子模拟和生物医学科研写作。
8. 浅色和深色主题均具备清晰层级；桌面宽屏为主要布局，右栏提供紧凑伴随视图。

### 3.2 非目标

- 不替换 DSH 的会话、模型、权限和审批系统。
- 不把自动检查包装成期刊接收保证。
- 不在没有证据时自动确认 Result 或自动推进投稿阶段。
- 不在本轮建设完整项目管理平台或通用实验室信息系统。

### 3.3 反目标

以下结果即使技术上能运行，也视为失败：

- 用户仍需复制命令到对话框才能完成常见工作；
- 只换颜色、圆角和图标，主流程仍不可操作；
- 团队页继续承担技能安装；
- 页面暴露大量英文枚举、内部工具名或版本口号；
- 按钮提交后只显示“失败”，不说明下一步；
- 用虚构的进度或自动生成内容冒充真实科研完成度。

## 4. 实现路线比较

### 路线 A：仅重做右侧栏

保留当前三个标签，只重新排版和增加按钮。

优点：改动较小。  
缺点：右栏宽度限制明显；入口仍隐藏；难以同时表达论文结构、任务 DAG 和图表；工作台仍是对话的附属视图。  
结论：不采用。

### 路线 B：完整主工作台 + 右栏快捷视图

在 DSH `main` 区域注册独立“科研工作台”面板，并在左侧全局面板提供直接入口。现有右栏改为紧凑视图，只展示阶段、下一步、运行任务和快捷跳转。

优点：工作台成为主界面；仍可通过右栏与对话并行；可以使用完整网页布局；沿用 DSH 会话和权限。  
缺点：需要重构客户端模块和建立可靠的工作流动作接口。  
结论：采用。

### 路线 C：独立外部 Web 应用

单独运行前端和后端，再连接 DSH。

优点：视觉自由度最高。  
缺点：认证、会话、部署、插件安装和状态同步全部复杂化。  
结论：不采用。

## 5. 信息架构与中文命名

主入口名称保持“科研工作台”。主页面包含四个一级页面：

| 当前名称 | 新名称 | 用途 |
| --- | --- | --- |
| 论文驾驶舱 | 论文主线 | 论文阶段、文章结构、Result 和下一步动作 |
| 团队执行 | 团队进展 | 只展示成员、任务、依赖、阻塞和回报 |
| 图表与产物 | 图表与成果 | 直接预览图表，集中查看文件、文稿、审查和汇报 |
| 角色技能库 | 专家配置 | 管理专家增强能力，与执行页面完全分离 |

用户界面用词调整：

| 内部术语 | 用户界面用词 |
| --- | --- |
| DSH Evidence Spine / 论文证据主干 | 论文主线 |
| Core claim | 核心研究结论 |
| Claim | 可验证主张（首次出现），后续简称“主张” |
| Evidence | 证据 |
| Result | 研究结果（Result，首次出现），后续简称“结果” |

## 6. 主界面设计

### 6.1 整体框架

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 科研工作台   项目标题                  当前阶段   总进度   打开对话 │
├──────────────────────────────────────────────────────────────────────┤
│ 论文主线 │ 团队进展 │ 图表与成果 │ 专家配置                         │
├──────────────────────────────────────────────────────────────────────┤
│ ①研究探索 ─ ②文章结构 ─ ③任务细化 ─ ④分析绘图 ─ ⑤论文写作 ─ ⑥汇报投稿 │
├───────────────────────────────────────┬──────────────────────────────┤
│ 当前阶段内容 / Result 卡片 / 结构图   │ 下一步建议                   │
│                                       │ 阻塞原因                     │
│ [开始探索] [优化结构] [细化任务]      │ [继续下一步] [提出修改]      │
├───────────────────────────────────────┴──────────────────────────────┤
│ 最近活动、运行任务、生成成果                                        │
└──────────────────────────────────────────────────────────────────────┘
```

宽屏采用 12 列布局；中等宽度变成 8 列；右栏伴随视图和窄屏使用单列。主内容最大宽度受控，避免全屏后内容被横向拉散。

### 6.2 首次使用空态

没有论文主线时不显示空白指标和内部命令，而显示起始页：

- 标题：“开始一项研究”
- 说明：“从一个研究问题开始，或导入已经完成的结果。”
- 主输入：“你想探索什么问题？”
- 主按钮：“开始探索”
- 次按钮：“导入已有结果”
- 下方用三张短卡解释：探索问题 → 组织结果 → 执行与写作。

### 6.3 阶段流程

用户可见的六个阶段：

1. 研究探索：输入问题、范围、已有数据、算力和时间约束。
2. 文章结构：生成核心结论候选和 Result 结构；逐项确认或修改。
3. 任务细化：把已确认 Result 拆成可执行任务和依赖关系。
4. 分析与绘图：执行分析、模拟和绘图；图表直接回流对应 Result。
5. 论文写作：按已确认结果撰写或重写文章；允许补充期刊和语言要求。
6. 汇报与投稿：制作汇报 PPT，完成数据代码、伦理、报告规范和局限性检查。

每一阶段提供三类动作：

- 推进：开始、生成、细化、绘图、撰写、制作汇报；
- 修改：打开简短输入框，说明希望怎样调整；
- 确认：触发原生审批流程，确认后才允许进入依赖该确认的执行动作。

### 6.4 Result 卡片

每个结果卡片显示：

- 人类可读标题，不以 `res-1` 作为视觉主标题；
- 当前状态和是否已确认；
- 科学证据、执行任务、图表呈现、写作材料四项完成度；
- 阻塞原因，按“必须处理 / 建议处理”区分；
- 关键证据和参考文献摘要；
- 直接动作：`查看详情`、`优化`、`细化任务`、`开始绘图`、`确认并继续`。

卡片展开后才展示修订编号、证据定位和审查记录等专业细节。

## 7. 工作流动作接口

建立一个深模块 `workflow-actions`，把按钮背后的复杂性隐藏在小接口后：

```js
buildWorkflowRequest({ action, paperState, targetId, userInput })
submitWorkflowRequest({ session, request })
```

模块负责：

- 根据动作生成稳定、可测试的会话消息；
- 带上当前 Result、阶段和用户补充要求；
- 生成实际 `/sci-*` 技能手势，使 DSH 确定性注入技能正文；
- 检查确认闸门和必需输入；
- 返回可操作错误，不让页面只显示“处理失败”；
- 为按钮提供 `idle / submitting / accepted / rejected` 状态。

第一批动作映射：

| UI 动作 | 会话请求 |
| --- | --- |
| 开始探索 | `/sci-hypothesis`，附研究问题和资源约束 |
| 扩展文献探索 | `/sci-research`，附当前问题和已有 Result |
| 生成文章结构 | 结构化请求队长建立核心结论与 Result 草案 |
| 优化结构 / 修改 Result | 结构化请求，限定目标和用户修改说明 |
| 确认并继续 | 请求调用蓝图确认工具，由 DSH 显示原生审批卡 |
| 细化任务 | 请求为已确认 Result 建立任务和依赖；未确认时在客户端阻止 |
| 开始绘图 | `/sci-figures`，带 Result、证据、目标期刊和图件要求 |
| 撰写论文 | `/sci-writing`，带当前论文主线和用户补充要求 |
| 制作汇报 PPT | `/sci-slides`，只使用现有结果，不创造新证据 |

`/sci-hypothesis` 等宿主命令必须使用合法 `UserMessage`，不能再传字符串。命令写入的文本保留 `/skill-name` 手势，使宿主在 pre-step 确定性注入技能。

## 8. 团队进展页

团队进展页只回答三个问题：谁在做、做到哪里、哪里受阻。

页面组成：

1. 顶部状态：运行中、等待中、已完成、受阻数量和最近更新时间。
2. 成员带：头像、专家名称、当前任务、实时状态和最近回报；点击打开成员会话。
3. 任务图：默认显示依赖关系和关键路径；可切换列表视图。
4. 阻塞区：只显示真正阻断后续任务的事项，并提供“查看上游”“请求处理”。
5. 回报时间线：成员提交的结果摘要、对应 Result 和时间。

不再出现安装复选框、自定义 Git 地址或技能仓库说明。

## 9. 图表与成果页

图表区改为可直接浏览的响应式画廊：

- PNG/JPEG/WebP/SVG 直接显示缩略图；
- 保留原始纵横比，点击进入大图预览；
- 显示所属 Result、版本、尺寸、前检状态和人工终审状态；
- 支持上一版本对比；
- 无法预览的 PDF/其他文件显示明确文件卡和打开按钮；
- 空态提供“基于现有 Result 开始绘图”主按钮。

成果区按“图表、论文文稿、汇报材料、数据与代码、审查记录”分组，不再把所有文件平铺在同一层级。

## 10. 专家配置页

页面按专家角色展示“内置能力”和“可选增强”，安装行为不再出现在团队页。卡片说明增强能力实际解决什么问题、依赖什么环境、许可证和是否已安装。

目录调整方向：

### 10.1 计算模拟专家

- 分子动力学：GROMACS、OpenMM、NAMD 等；
- 蛋白质结构与复合物预测：AlphaFold/ColabFold、Boltz、Chai 等环境搭建与运行；
- 分子对接和虚拟筛选：AutoDock Vina、gnina 等；
- 量子化学与第一性原理：ORCA、Gaussian、Quantum ESPRESSO 等；
- 化学信息学：RDKit 和分子表示处理。

删除默认燃烧和 CFD 项。若用户自行安装，仍允许通过“自定义扩展”添加，但不作为生物科研推荐项。

### 10.2 模型训练专家

- 蛋白质语言模型：ESM、ProtT5 等模型的表示提取和微调；
- 生物分子基础模型的参数高效微调；
- Hugging Face / PEFT / PyTorch Lightning 的可复现训练；
- 生物序列、结构和多模态数据集处理。

### 10.3 科研绘图专家

- 生物统计和组学图表；
- 蛋白质结构和分子互作图；
- 生物机制示意图和通路图；
- 期刊级统计图、组合图和可编辑矢量输出；
- BioRender 作为可选独立集成，不伪装成本地开源库。

### 10.4 数据分析专家

- NGS、单细胞、空间组学、蛋白质组和常规生物统计；
- 通用大数据处理放到“高级选项”，不占默认推荐位。

所有具体仓库在进入目录前必须核对：仓库可达、许可证、维护状态、SKILL.md 结构、安装副作用和与目标角色的相关性。

## 11. 视觉系统

1. 使用独立 CSS 类体系替换大部分行内样式；颜色继续基于 DSH 主题变量。
2. 采用 8px 间距体系、12px 卡片圆角、清晰的 14/16/20px 字级层次。
3. 页面背景、卡片、强调区和悬浮层建立明确的三层表面层级。
4. 主操作使用实色按钮；次操作用轻量边框；危险和阻塞只在真正需要时使用红色。
5. 进度使用阶段轨、环形/条形指标和状态徽章组合，不用密集小字承担全部表达。
6. 动画仅用于状态变化、展开和运行中反馈，并尊重 `prefers-reduced-motion`。
7. 所有图标按钮有可访问名称；键盘可达；焦点态清晰。
8. 右栏紧凑视图只保留当前阶段、下一步和运行任务，不复制完整主页面。

## 12. 错误与恢复

工作流动作失败时统一显示：

- 发生了什么；
- 是否已提交到会话；
- 用户能做什么；
- `重新提交`、`打开对话`、`复制诊断信息`三个入口中适用的部分。

典型错误文案：

- 未选择会话：“当前没有可接收任务的会话。请先新建或打开一个会话。”
- 模型不可用：“当前会话尚未配置模型。请先在模型设置中选择可用模型。”
- Result 未确认：“该结果尚未确认，不能细化正式执行任务。请先确认，或继续修改。”
- 网络/宿主拒绝：“任务未被 DSH 接收；未产生任何研究改动。可以安全重试。”

## 13. 模块拆分

将当前超大 `client-src/index.jsx` 拆为有限数量的深模块：

- `client-src/index.jsx`：注册主面板、右栏和宿主服务适配；
- `client-src/workflow-actions.js`：工作流动作构建、校验和提交；
- `client-src/workbench.jsx`：页面框架和路由；
- `client-src/pages/paper.jsx`：论文主线；
- `client-src/pages/team.jsx`：团队进展；
- `client-src/pages/artifacts.jsx`：图表与成果；
- `client-src/pages/experts.jsx`：专家配置；
- `client-src/ui.jsx`：少量通用展示模块；
- `client-src/styles.js`：集中式 CSS 字符串，构建后仍只输出一个客户端 JS。

宿主状态读取、动作提交和成员会话跳转分别放在清晰的 seam 后，不把 DSH 服务对象散落到页面模块。

## 14. 测试 seam 与完成判据

建议确认以下公共 seam：

1. **工作流命令 seam**：给定命令输入，必须排入合法 `UserMessage`，且正文包含准确 `/skill-name`；捕获本次“处理失败”。
2. **工作流动作 seam**：给定 action、论文状态和用户输入，输出确定的请求或可操作阻塞原因；捕获错误映射和确认闸门。
3. **状态视图 seam**：给定 `/state` 快照，四个页面产生正确的阶段、Result、任务、图表和专家状态。
4. **浏览器交互 seam**：真实 DSH Web 中能从左侧入口打开主工作台，完成“开始探索 → 输入要求 → 提交”，并能切换四个页面。
